Project Context

I am building a Spring Boot backend for a real estate application.

The application has:

Firebase Authentication
Buyer and Agent accounts
Property listings
Property images (AWS S3)
Reservations
Real-time chat using Spring WebSocket + STOMP
Firebase Cloud Messaging (FCM) for offline chat notifications
Device token management
Global exception handling

The project follows a domain-based architecture.

Security Architecture

Current REST authentication flow:

Mobile App
     |
Authorization: Bearer FirebaseToken
     |
FirebaseAuthenticationFilter
     |
FirebaseAuth.verifyIdToken()
     |
Spring SecurityContext
     |
Authentication.getName()
     |
Firebase UID

This replaces the insecure approach:

RequestHeader("userId")

Important Rules
Do not reintroduce userId headers.
Always use Authentication.getName() for REST.
Use Principal.getName() for WebSocket.
DeviceToken should remain separate from Buyer/Agent.
Keep Firebase logic separated from chat services.
Keep MessageDispatcher responsible only for choosing WebSocket or FCM.
